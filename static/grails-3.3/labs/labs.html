1. Fundamentals

  1. Strings and Groovy Strings

    1. Create a script called strings.groovy

    2. Add a statement to print a sentence, and execute the script

      println 'this is a sentence'

    3. Use the length method from Java and the size method from Groovy to print the number of characters

      String s = 'this is a sentence'
println s.length()
println s.size()

    4. Check programmatically that they give the same result

      String s = 'this is a sentence'
println s.length()
println s.size()
assert s.length() == s.size()

    5. Use array access (the [] operator) to print the first word.

      // ... add to script ...
println s[0..3]

    6. Print out the reverse of the first word

      println s[3..0]

    7. Reverse the string using the array indices

      println s[-1..0]

    8. Reverse the string using the reverse method from the Groovy JDK

      println s.reverse()

    9. Use the + operator and check that it does not affect the original string

      println s + ' with more words'
assert s == 'this is a sentence'

    10. Use the - operator to see how it works

      println s - 'is'

    11. Chain minus operations together

      println s - 'is' - 'is'

    12. Add a variable with your name and interpolate it into a Groovy string

      String name = 'Dolly'
println "Hello, ${name}!"

    13. Try the same expression without the braces

      String name = 'Dolly'
println "Hello, $name!"

    14. Try it with single quotes instead

      String name = 'Dolly'
println 'Hello, $name!'

2. Collections

  1. Ranges

    1. Create a range from -3 to 3

      def nums = -3..3

    2. Verify that it is inclusive

      assert nums.contains(-3)
assert nums.contains(3)

    3. Invoke the getFrom and getTo methods using the normal Groovy idiom of accessing properties

      assert nums.from == -3
assert nums.to == 3

    4. Create an open range and check its limits

      nums = -3..<3
assert nums.contains(-3)
assert !nums.contains(3)
assert nums.from == -3
assert nums.to == 2

    5. Try a range of Date instances and the format method from the Groovy JDK

      Date now = new Date()
Date then = now + 3
(now..then).each {
    println it.format('MMM dd, yyyy')
}

  2. Lists

    1. Create a list of strings and check the default class

      def strings = ['Red Sox', 'Yankees']
assert strings.class == java.util.ArrayList

    2. Use the left-shift and plus operators to append to the list

      assert strings + ['Orioles', 'Blue Jays'] ==
  ['Red Sox', 'Yankees', 'Orioles', 'Blue Jays']
assert strings == ['Red Sox', 'Yankees']

strings << ['Orioles', 'Blue Jays']
assert strings == ['Red Sox', 'Yankees', ['Orioles', 'Blue Jays']]

    3. Use the minus operator to remove an element

      assert strings - 'Yankees' ==
    ['Red Sox', ['Orioles', 'Blue Jays']]

    4. Try ranges and indices

      println strings[0..2]
println strings[-3..-1]
println strings[1..-1]
println strings[0, 2]

    5. Use the flatten method

      strings = strings.flatten()
assert strings == ['Red Sox', 'Yankees', 'Orioles', 'Blue Jays']
def nums = [3, [1, [4, [1, 5], 9], 2], 6]
assert nums.flatten() == [3, 1, 4, 1, 5, 9, 2, 6]

    6. Use the spread-dot operator and collect

      assert strings*.size() == [7, 7, 7, 9]
assert strings.collect { it[0..2].toLowerCase() } ==
    ['red', 'yan', 'ori', 'blu']

    7. Use the join method

      nums = nums.flatten()
assert nums.join(',') == '3,1,4,1,5,9,2,6'
assert nums.join('***') == '3***1***4***1***5***9***2***6'

  3. Maps

    1. Start with an empty map

      def map = [:]

    2. Add elements using dot operator, putAt, and put methods

      def map = [:]
map.k1 = 'v1'
map['k2'] = 'v2'
map.put('k3', 'v3')

assert map.k1 == 'v1'
assert map['k2'] == 'v2'
assert map.get('k3') == 'v3'

println map.keySet()
assert map.keySet() == ['k1', 'k2', 'k3'] as Set
println map.entrySet()
println map.values()
assert map.values() as List == ['v1', 'v2', 'v3']

    3. Check the size of the collection

      assert map.keySet().size() == 3
assert map.entrySet().size() == 3
assert map.size() == 3

    4. Create a query string from the map

      assert map.collect { k,v -> "$k=$v" }.join('&') == 'k1=v1&k2=v2&k3=v3'

  2. A new Grails application

    1. Create a new Grails application called hello using the grails create-app command. Once it completes, change directory into the hello app.

      NOTE: If you use the Grails Application Forge at http://start.grails.org, use the latest version of Grails and select the `web` profile with all its defaults.

    2. Open the file application.yml in the grails-app\conf folder. Near the top you’ll find a setting called defaultPackage, nested under grails: and codegen:. Change the value from hello (the default package name is the same as the app name) to com.mycompany (adjust the actual name as desired)

    3. Use the command create-controller Welcome to create a new controller called com.mycompany.WelcomeController (this should use the defaultPackage setting you changed in the previous step).

    4. In the WelcomeController class, what is the default action? What URL corresponds to this action? What would happen if we started the application and accessed this action now? (If you’re not sure, try it and see.)

  3. Render

    1. Inside the index action in the WelcomeController class, add a line rendering the phrase Hello, World!.

      def index() {
    render "<h2>Hello, World!<\h2>"
}

    2. Start the application (if not already started) using the grails run-app command and click on the WelcomeController link to access the action.

    3. Inside the index action, declare a String variable called n. Assign it to the value of the name property in the incoming request. If params.name is null or empty, default to the word World. Change the render to use the n value.

      Note
      		 This is a perfect opportunity to use the Elvis operator from Groovy. 
      def index() {
    String n = params.name ?: 'World'
    render "<h2>Hello, $n!</h2>"
}

    4. To test the render operation, open the WelcomeControllerSpec class in the hello/test/unit/com/mycompany/ directory. As of Grails 2.3, the default testing mechanism uses the Spock plugin, so the test extends spock.lang.Specification.

    5. The setup and cleanup methods are not required for this exercise. You can delete those methods or ignore them, whichever you prefer.

    6. Add tests for the index action both with an without a name. Use Spock’s when/then construct to do so. Note that you can use the supplied params map to set the input name parameter before invoking the index action.

      void "index without name should say Hello, World!"() {
    when:
    controller.index()

    then:
    response.text == '<h2>Hello, World!</h2>'
}

void "index with name should say Hello, name"() {
    when:
    params.name = 'Dolly'
    controller.index()

    then:
    response.text == '<h2>Hello, Dolly!</h2>'
}

  4. Redirect

    1. Before implementing redirect, you need an action to redirect to. Add a new action to the WelcomeController called greet, which takes a single String argument called name and returns def. What is the URL corresponding to this action?

    2. Implement the greet action to use the name argument (note: only slight variation on current index implementation):

      def greet(String name) {
    String n = name ?: 'World'
    render "<h2>Hello, $n!</h2>"
}

    3. Test the greet action by revising the current tests for index. Note that you can supply the name as a method argument now, rather than a params value.

      void "greet without name should say Hello, World!"() {
    when:
    controller.greet()

    then:
    response.text == '<h2>Hello, World!</h2>'
}

void "greet with name should say Hello, name"() {
    when:
    controller.greet('Dolly')

    then:
    response.text == '<h2>Hello, Dolly!</h2>'
}

    4. Now you can re-implement the index action to redirect to the greet action.

      def index() {
    redirect(action:'greet')
}

    5. Access the URL corresponding to the index action, without supplying a name parameter. Verify that you see the string 'Hello, World!' in the display.

    6. Add a name parameter to the URL for the index action and access the URL. Does the parameter get passed to the hello action? Why not?

    7. Add a second argument to the redirect method to pass the input parameters to the next request and try again. The supplied name should now show in the response.

      def index() {
    redirect(action:'greet', params:params)
}

    8. To test the redirect, add the following tests:

      void "index without name should redirect to greet without name"() {
  when:
  controller.index()

  then:
  response.redirectedUrl == '/welcome/greet'
}

void "index with name should redirect to greet with a parameter"() {
  when:
  params.name = 'Dolly'
  controller.index()

  then:
  response.redirectedUrl == '/welcome/greet?name=Dolly'
}

  5. Return

    1. Add a new action called hi to the WelcomeController class, with no arguments.

    2. This time, have the action return a map with one entry. The key in the entry should be person and the value is the n variable. Remember, the return keyword itself is optional. The complete implementation is shown below.

      def hi() {
    String n = params.name ?: 'World'
    [user:n]
}

    3. Create a Groovy Server Page called hi.gsp in the welcome folder under grails-app\views. Give it a simple HTML structure (root element of <html>, with a <head> section and a <body> section). In the head section, add a meta tag to tell Grails to use the default SiteMesh layout.

      In the body, add a <div> element with the CSS class body. Inside the <div>, add an <h2> element that displays "Hello, ${user}!". The complete code is shown below.

      <html>
  <head>
    <meta name="layout" content="main">
    <title>Greeting</title>
  </head>
  <body>
    <div class="body">
    <h2>Hello, ${user}!</h2>
    </div>
  </body>
</html>

    4. Start the server and access the hi action with a URL, once without a name parameter and once with one. Stop the server when you’re done.

    5. Add two tests for the hi action, one with a name and one without. Check that the returned map has the proper person key in it.

      void "hi without name should return map with user == 'World'"() {
    when:
    def model = controller.hi()

    then:
    model.user == 'World'
}

void "hi with name should return map with user == name"() {
    when:
    params.name = 'Dolly'
    def model = controller.hi()

    then:
    model.user == 'Dolly'
}

    6. Execute the grails test-app com.mycompany.WelcomeController and check the resulting output to make sure everything works.

5. Creating A New Grails Application

  1. Create the application

    1. Create an application called holygrails using the web profile with all the defaults. If you create the app from the command line, move into the application directory when you are finished.

    2. In application.yml, change the defaultPackage to your own domain. These materials will use com.kousenit, but as long as you use your own package consistently, any value is fine.

  2. Add a domain class and a scaffolded controller

    1. Create a domain class called Quest using the create-domain-class wizard.

    2. Add an attribute called name of type String to the Quest class.

      class Quest {
    String name
    // ...
}

    3. Generate a controller and views using the generate-all command

      > grails generate-all com.kousenit.Quest

  3. Avoiding blank names

    1. Start the embedded Tomcat server:

      > grails run-app

    2. Browse to the application home page, http://localhost:8080 and select the QuestController link

    3. Create a new quest with any name you like (e.g., Seek the grail), edit it, and (optionally) delete it

    4. Try to create a quest with an empty name. Grails refuses to submit the form without a name. This is HTML5 client side validation.

    5. Type a few spaces in the Name field and submit again. You’ll see that Grails gives an error that says the name field in Quest cannot be null. By default, Grails trims the input text, and if it is empty, the validator submits a null, and all fields in a domain class are marked NOT NULL in the database by default.

    6. Change this behavior by going back to application.yml and changing the following setting +

grails:
    databinding:
        convertEmptyStringsToNull: false

  1. Since the application.yml file is read only on startup, you’ll need to restart the server. Do so, and see the new behavior when submitting a Name consisting of all spaces.

  2. In the Quest class, in the constraints section, add the restriction that the name cannot be blank:

    static constraints = {
    name(blank: false)
}

  3. The Grails user guide shows that the default error key for blank constraints is className.propertyName.blank. In the messages.properties file in the i18n directory add the line:

    quest.name.blank=Quests must have a name

  4. Re-submitting the quest with a blank name should give the new error message. (You may need to restart the server to see the new error message.)

6. Adding Another Domain Class

  1. Add a Task class

    1. Use the create-domain-class wizard to make a new domain class called Task

    2. Add the following attributes to the Task

      class Task {
    String name
    int priority = 3
    Date startDate = new Date()
    Date endDate = new Date()
    boolean completed
}

    3. Add constraints to the Task properties

      static constraints = {
    name blank:false
    priority range: 1..5
    startDate()
    endDate validator: { val, task ->
        val >= task.startDate
    }
    completed()
}

    4. Generate the controller and views for the Task

      > grails generate-all com.kousenit.Task

  2. Relationships

    1. Establish a one-to-many relationship between Quest and Task by adding to the Quest.groovy file:

      static hasMany = [tasks:Task]

    2. Ensure that deleting a quest deletes all associated tasks by adding to Task.groovy:

      static belongsTo = [quest:Quest]

    3. Re-start the server, add a quest, save it, then add a few tasks. Note that you can traverse from a quest to its tasks and from a task to the quest it belongs to. Delete the quest and note how the tasks also vanish.

    4. Add a toString method (which will override the one from Object) in Quest:

      String name  // (already there)
String toString() { name }

    5. Generate a toString method in Task using the AST Transformation:

      import groovy.transform.ToString
@ToString(includes = ['name','priority','completed'])
class Task {
    // ...
}

  3. Transient property

    1. Add a getter method for duration to Task

      int getDuration() { endDate - startDate + 1 }

    2. Declare the duration property in a transients list

      static transients = ['duration']

  4. Optional properties

    1. Back in Quest, add Hibernate-managed properties

      class Quest {
    Date dateCreated
    Date lastUpdated
    // ...
}
Note
 The dateCreated and lastUpdated fields do not display on the current scaffolding. They are in the database, however, which will be demonstrated in an upcoming exercise.

7. Unit Testing Domain Classes

  1. Unit test the Quest

    1. Open the file QuestSpec.groovy in the src/test/groovy hierarchy and add a Quest attribute with a non-null name value

      // inside class QuestSpec
    Quest q = new Quest(name:'name')

      1. Add a test to check that the quest attribute is valid

        void "the default quest is valid"() {
    expect: q.validate()
}

      2. Add a test to check that an empty name fails as expected

        void "blank names are not valid"() {
    when:
    q = new Quest(name: ' ')

    then:
    !q.validate()
    'blank' == q.errors['name'].code
}

      3. Execute the unit test and check the test report

        > grails test-app com.kousenit.Quest

  2. Unit test the Task

    1. Open the file TaskSpec.groovy and add attributes for a valid Quest and a valid Task (recall that we already initialized the priority, startDate, and endDate fields to valid values). The @Shared annotation is used when a property should not be re-initialized between tests (@Shared is in the spock.lang package)

      @Shared Quest q = new Quest(name: 'q')
Task t = new Task(name:'name', quest: q)

    2. After adding each of the following tests, verify that they pass using

      > grails test-app com.kousenit.Task

    3. Check the getDuration method

      void 'check the default duration should be 1'() {
    // default task has equal start and end dates
    expect: 1 == t.duration
}

void 'check the duration calculation'() {
    when: 'end date is 1 beyond start date'
    t.endDate = t.startDate + 1

    then: 'the duration is 2'
    2 == t.duration
}

    4. Verify that the default task is valid

      void 'default task is valid'() {
    expect: t.validate()
}

    5. Test that a blank name fails as expected

      void 'blank name is not valid'() {
    when:
    t = new Task(name: ' ', quest: q)

    then:
    !t.validate()
    'blank' == t.errors['name'].code
}

    6. Check that priorities too low fail

      void 'priorities below 1 are not valid'() {
    when:
    t.priority = 0

    then:
    !t.validate()
    'range.toosmall' == t.errors['priority'].code
}

    7. Do the same for priorities too high

      void 'priorities above 5 are not valid'() {
    when:
    t.priority = 6

    then:
    !t.validate()
    'range.toobig' == t.errors['priority'].code
}

    8. Check that valid priorities work properly using the cool @Unroll annotation from Spock. Note that you will need to add import spock.lang.Unroll to the set of existing import statements.

      @Unroll
void 'task with priority #p is valid'() {
    when:
    t.priority = p

    then:
    t.validate()

    where:
    p << (1..5)
}

    9. Check that end dates before the start date fail

      void 'endDate before startDate fails'() {
    when:
    t.endDate = t.startDate - 1

    then:
    !t.validate()
    'validator.invalid' == t.errors['endDate'].code
}

    10. In each case, run the unit tests and correct any errors

9. Dynamic finders and criteria queries, part 2

  1. Dynamic finders

    1. Continuing from the previous exercise, try a couple of dynamic finders (one at a time, or add println in front of each).

      Quest.findByName('Seek the grail')
Task.findAllByPriorityGreaterThan(2)
Task.findAllByPriorityLessThanAndStartDateBetween(
    4, new Date() - 1, new Date() + 1)

    2. Try out the count method and others

      Task.count()
Task.listOrderByName()

  2. Criteria Queries

    1. Do a basic criteria query on Task

      Task.withCriteria {
    ilike('name', '%e%')
}

    2. Add conditions

      Task.withCriteria {
    ilike('name', '%e%')
    between('startDate', new Date() - 1, new Date() + 1)
    lt('priority', 4)
}

    3. Ordering works, too

      Task.withCriteria {
    ilike('name', '%e%')
    between('startDate', new Date() - 1, new Date() + 1)
    lt('priority', 4)
    order('name', 'asc')
}

    4. Try a criteria query on Quest that uses a join

      Quest.withCriteria {
    ilike('name', '%e%')
    tasks {
      ilike('name', '%e%')
      gte('priority', 2)
    }
}

  3. Where queries

    1. Try a non-lazy where query

      Task.findAll {
    priority > 2
}

    2. Add a like clause

      Task.findAll {
    priority > 2 && name ==~ '%e%'
}

    3. Use an in clause

      Task.findAll {
    priority in [1, 3, 5]
}

    4. Define a lazy query and invoke it

      def query = Task.where {
    priority > 2
}

query.list()

    5. Sort the results by name

      def query = Task.where {
    priority > 2
}

query.list(sort:'name', order:'desc')

    6. Can even do associations and sub-queries

      def query = Quest.where {
    name ==~ '%e%'
    tasks {
        priority >= avg(priority)
    }
}

query.list(sort:'name')

10. Complete the domain model

  1. Knights

    1. Add a Knight domain class

      > grails create-domain-class Knight

    2. Knights have titles and names

      class Knight {
    String title
    String name
}

    3. Add appropriate constraints

      static constraints = {
    title inList: ['Sir', 'Lord', 'Lady', 'King', 'Queen']
    name blank: false
}

    4. Quests have many knights, too

      class Quest {
    // ...
    static hasMany = [tasks:Task, knights:Knight]
}

    5. Knights know which quest they are on

      class Knight {
    Quest quest
}

    6. Knights can be between quests

      static constraints = {
    // as above, and
    quest nullable: true
}

    7. Add a toString method to Knight

      String toString() { "$title $name" }

    8. Generate a controller and views for Knight

      > grails generate-all com.kousenit.Knight

  2. Castles

    1. Add a Castle domain class

      > grails create-domain-class Castle

    2. Castles are really just named locations

      class Castle {
    String name
    String city
    String state
    double latitude
    double longitude
}

    3. Add appropriate constraints

      static constraints = {
    name blank:false
    city blank:false
    state blank:false
    latitude min:-90d, max:90d  // South Pole to North Pole
    longitude()
}

    4. Castles need a toString method, too

      String toString() { "$name Castle" }

    5. Castles contain knights

      static hasMany = [knights:Knight]

    6. Knights know their castles

      class Knight {
    // as before
    Castle castle
}

    7. But Knights can be between castles, too

      static constraints = {
    // other Knight constraints
    castle nullable: true
}

    8. Add a some castles and knights to the bootstrap data

      def init = { servletContext ->
  // existing quest and tasks
    Castle camelot = new Castle(name:'Camelot', city:'Boston', state:'MA')
        .addToKnights(title:'King', name:'Arthur', quest:q)
        .addToKnights(title:'Sir', name:'Lancelot', quest:q)
        .addToKnights(title:'Sir', name:'Robin', quest:q)

}

    9. Add another castle near by (will be useful later)

15. Calling stored procedures

  1. Set up the Sakila data source

    1. If you haven’t already done so, set up the Sakila database and data source using steps in the previous exercise.

  2. Create a service

    1. Create a service called StoredProcService in the sakila package. Be careful not to put the word Service at the end of the command.

      > grails create-service StoredProc

    2. Replace the existing serviceMethod (or whatever the default is) with the stub of our implementation method:

      The structure of the getNumberOfFilmsInStock method
      int getNumberOfFilmsInStock(filmId, storeId) {
    return 0
}

    3. To test a stored procedure, we need to use the real database. Therefore, create an integration test for the new service. The wizard that created the service generated a unit test called StoredProcServiceTests, so we need to use a different name.

      > grails create-integration-test StoredProcServiceIntegration

  3. Implement the integration test

    1. The documentation for the film_in_stock stored procedure is located at https://dev.mysql.com/doc/sakila/en/sakila-structure-procedures-film_in_stock.html. Note that it takes two input parameters, p_film_id and p_store_id, representing the film and store, and one output parameter, p_film_count, which gives the number of copies of that film at that store. The documentation shows that for film 1 at store 1, the procedure returns 4.

    2. Since this is an integration test, we can take advantage of Grails’s dependency injection for the service.

      @Integration
@Rollback
class StoredProcServiceIntegrationSpec extends Specification {
    @Autowired
    StoredProcService storedProcService
}

    3. Implement the test.

      @Integration
@Rollback
class StoredProcServiceIntegrationSpec extends Specification {
    @Autowired
    StoredProcService storedProcService

    void 'should be 4 copies of film 1 in store 1'() {
        expect:
        4 == storedProcService.getNumberOfFilmsInStock(1, 1)
    }

    void 'should be 3 copies of film 1 in store 2'() {
        expect:
        3 == storedProcService.getNumberOfFilmsInStock(1, 2)
    }
}

    4. Now run the test and watch it fail.

      Tip
      		 As they saying goes, never trust a test you haven’t seen fail. 
      > grails test-app -integration

  4. Implement the service

    1. Inject the data source into the service

      class StoredProcService {
    def dataSource

    int getNumberOfFilmsInStock(filmId, storeId) {
        return 0
    }
}

    2. Define the stored procedure call using the JDBC escape syntax (inside the getNumberOfFilmsInStock method).

      String sqlTxt = '{call film_in_stock(?,?,?)}'

    3. Use the groovy.sql.Sql class to connect. Use the injected data source as the argument to the Sql constructor.

      Sql db = new Sql(dataSource)  // import groovy.sql.Sql

    4. Implement the call

      db.call(sqlTxt, [filmId, storeId, Type.INTEGER]) { count ->
    println count
}

    5. Since returning from a closure only returns from the closure and not the method, use a temporary variable to return the result. Here is the complete class.

      class StoredProcService {
    def dataSource

    int getNumberOfFilmsInStock(filmId, storeId) {
        String sqlTxt = '{call film_in_stock(?,?,?)}'
        Sql db = new Sql(dataSource)
        int result = 0
        db.call(sqlTxt, [filmId, storeId, Sql.INTEGER]) { count ->
            println count
            result = count
        }
        return result
    }
}

    6. The integration test should now run successfully.
