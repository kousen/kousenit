1. Creating a New Project

  1. Go to http://start.spring.io to access the Spring Initializr

  2. In the "Generate a" drop-down, switch from "Maven Project" to "Gradle Project"

  3. Specify the Group as com.kousenit, the Artifact as demo, and the language as Kotlin

  4. Add the "Web" and "Thymeleaf" dependencies

  5. Click the "Generate Project" button to download a zip file containing the project files

  6. Unzip the downloaded "demo.zip" file into any directory you like (but remember where it is)

  7. Import the project into your IDE

    1. If you are using IntelliJ IDEA, import the project by selecting the "Import Project" link on the Welcome page and navigating to the build.gradle file inside the unzipped archive

    2. If you are using Spring Tool Suite (or any other Eclipse-based tool), generate an Eclipse project using the included gradlew script: Navigate to the project root directory in a command window and run the following command:

      > gradlew cleanEclipse eclipse
      Note
      		 On a Unix-based machine (including Macs), use ./gradlew for the command

    3. Now you should be able to import the project into Eclipse as an existing Eclipse project (File → Import…​ → General → Existing Projects Into Workspace)

  8. As part of the import process, the IDE will download all the required dependencies

  9. Open the file src/main/kotlin/com/kousenit/demo/DemoApplication.kt and note that it contains a standard Kotlin "main" function (with signature: fun main(args: Array<String>))

  10. There is a test for this class under src/test/kotlin/com/kousenit/demo/DemoApplicationTests. Execute the tests, just to show that everything starts up and shuts down properly.

  11. Add a controller by creating a class called com.kousenit.demo.controllers.HelloController in the src/main/kotlin directory

    Note
    		 The goal is to have the HelloController class in the com.kousenit.demo.controllers package starting at the root directory src/main/kotlin

  12. The code for the HelloController is:

    package com.kousenit.demo.controllers

import org.springframework.stereotype.Controller
import org.springframework.ui.Model
import org.springframework.ui.set
import org.springframework.web.bind.annotation.GetMapping
import org.springframework.web.bind.annotation.RequestParam

@Controller
class HelloController {
    @GetMapping("/hello")
    fun sayHello(@RequestParam(required = false, defaultValue = "World") name: String,
                 model: Model): String {
        model["user"] = name
        return "hello"
    }
}

  13. Note the import of org.springframework.ui.set. This is an operator extension function added to the Model class that invokes the addAttribute method in the underlying Java class. The array-like syntax, model["key"] = value, is implemented by this method.

  14. Create a file called hello.html in the src/main/resources/templates folder

  15. The code for the hello.html file is:

    <!DOCTYPE HTML>
<html xmlns:th="http://www.thymeleaf.org" lang="en">
<head>
    <title>Hello, World!</title>
</head>
<body>
    <h2 th:text="'Hello, ' + ${user} + '!'"></h2>
</body>
</html>

  16. Start up the application and navigate to http://localhost:8080/hello. You should see the string "Hello, World!" in the browser

  17. Change the URL in the browser to http://localhost:8080/hello?name=Dolly. You should now see the string "Hello, Dolly!" in the browser

  18. Shut down the application (there’s no graceful way to do that — just hit the stop button in your IDE)

  19. Add a home page to the app by creating a file called index.html in the src/main/resources/static folder

  20. The code for the index.html file is:

    <!DOCTYPE HTML>
<html lang="en">

</head>
<body>

        <b>Name: </b>

</html>

    > gradlew build

  22. Now you can start the application with a generated executable jar file:

    > java -jar build/libs/demo-0.0.1-SNAPSHOT.jar

  23. Navigate to http://localhost:8080 and see the new home page. From there you can navigate to the greeting page, and manually try adding a name parameter to the URL there

  24. Again stop the application (use Ctrl-C in the command window)

  25. Start it one more time using a special gradle task:

    > gradlew bootRun

  26. When again you’re happy the app is running properly, shut it down

    @Target(ElementType.TYPE)

  30. Because the controller is a simple POJO, you can unit test it by simply instantiating the controller and calling its sayHello method directly. To do so, add a class called HelloControllerUnitTests to the com.kousenit.demo.controllers package in the test folder, src/test/kotlin

  31. The code for the test class takes advantage of the assertAll function in JUnit 5, which ensures that all tests are executed even if some or all fail. It takes as an argument a vararg collection of Executable, which is a functional interface whose single abstract method takes no arguments and returns void. The bottom line is you can supply that method a series of Kotlin lambda expressions separated by commas, as here:

    package com.kousenit.demo.controllers

import org.junit.jupiter.api.Assertions.*
import org.junit.jupiter.api.Test
import org.junit.jupiter.api.assertAll
import org.springframework.validation.support.BindingAwareModelMap

@TestInstance(TestInstance.Lifecycle.PER_CLASS)  // One instance per test class
class HelloControllerUnitTests {
    @Test
    fun `test sayHello`() {
        val controller = HelloController()
        val model = BindingAwareModelMap()
        val result = controller.sayHello("World", model)
        assertAll(
                { assertEquals("hello", result) },
                { assertEquals("World", model["user"]) }
        )
    }
}

  32. Run the test by executing this class as a JUnit test. It should pass. It’s not terribly useful, however, since it isn’t affected by the request mapping or the request parameter.

  33. To perform an integration test instead, use the MockMVC classes available in Spring. Create a new class called HelloControllerMockMVCTests in the com.kousenit.demo.controllers package in src/test/kotlin

  34. The code for the integration test is below. Note the use of the Kotlin DSL (domain-specific language) for mock mvc tests.

    package com.kousenit.demo.controllers

import org.junit.jupiter.api.Test
import org.springframework.beans.factory.annotation.Autowired
import org.springframework.boot.test.autoconfigure.web.servlet.WebMvcTest
import org.springframework.http.MediaType
import org.springframework.test.web.servlet.MockMvc
import org.springframework.test.web.servlet.get

@WebMvcTest(HelloController::class)
class HelloControllerMockMVCTest(@Autowired val mvc: MockMvc) {

    @Test
    fun `check sayHello without name`() {
        mvc.get("/hello") {
            accept = MediaType.TEXT_PLAIN
        }.andExpect {
            status { isOk }
            view { name("hello") }
            model { attribute("user", "World") }
        }
    }

    @Test
    fun `check sayHello with name`() {
        mvc.get("/hello") {
            accept = MediaType.TEXT_PLAIN
            param("name", "Dolly")
        }.andExpect {
            status { isOk }
            view { name("hello") }
            model { attribute("user", "Dolly") }
        }
    }
}

  35. Note the quotes around the function is, which are necessary because is is a keyword in Kotlin. The tests should pass successfully. One of the advantages of the @WebMvcTest annotation over the generic @SpringBootTest annotation is that it allows you to automatically inject an instance of MockMvc, as shown.

2. Add a Rest Controller

  1. Add another class to the com.kousenit.demo.controllers package called HelloRestController. This controller will be used to model a RESTful web service, though at this stage it will be limited to HTTP GET requests (for reasons explained below).

  2. Add the @RestController annotation to the class.

  3. By default, REST controllers will serialize and deserialize Kotlin classes into JSON data using the Jackson 2 JSON library, which is currently on the classpath by default. To have an object (other than a trivial String) to serialize, add a Kotlin data class called Greeting to the same file below the controller class. In a larger application, this would represent a domain class that you can store in a database or other persistent storage mechanism and you would put it in its own package, but for the moment it is only used for JSON serialization so add it here for simplicity.

  4. The Greeting class shold have a private attribute of type String called message.

    data class Greeting(val message: String)

  5. In the HelloRestController, add a method called greet that takes a String called name as an argument and returns a Greeting.

  6. Annotate the greet method with a @GetMapping whose argument is "/rest", which means that the URL to access the method will be http://localhost:8080/rest .

  7. Add the @RequestParam annotation to the argument, with the properties required set to false and defaultValue set to World.

  8. In the body of the method, return a new instance of Greeting whose constructor argument should assign the message property to be "Hello, $name!".

  9. The full class looks like:

    package com.kousenit.demo.controllers

import org.springframework.web.bind.annotation.GetMapping
import org.springframework.web.bind.annotation.RequestParam
import org.springframework.web.bind.annotation.RestController

@RestController
class HelloRestController {

    @GetMapping("/rest")
    fun greet(@RequestParam(required = false,
            defaultValue = "World") name: String) : Greeting =
            Greeting("Hello, $name!")
}

data class Greeting(val message: String)

  10. You can now run the application and check the behavior using either curl or a similar command-line tool, or simply accessing the URL in a browser, either with or without a name.

  11. To create a test for the REST controller, use the TestRestTemplate class, which is a testing version of the RestTemplate that will be used in upcoming exercises. Add a class called HelloRestControllerTests in the src/test/kotlin tree in the same package as the REST controller class.

  12. This time, when adding the @SpringBootTest annotation, add the argument webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT. This will autoconfigure several properties of the test, including making a TestRestTemplate available to inject.

  13. Autowire in a val called template of type TestRestTemplate. This can be done in the primary constructor (i.e., in the parentheses after the class name declaration).

  14. Add two tests, one for greetings without a name and one for greetings with a name.

  15. The tests should look like:

    package com.kousenit.demo.controllers

import org.junit.jupiter.api.Test
import org.springframework.beans.factory.annotation.Autowired
import org.springframework.boot.test.context.SpringBootTest
import org.springframework.boot.test.web.client.TestRestTemplate
import org.springframework.boot.test.web.client.getForEntity
import org.springframework.boot.test.web.client.getForObject
import org.springframework.http.HttpStatus
import org.springframework.http.MediaType

@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
class HelloRestControllerTests(@Autowired val template: TestRestTemplate) {

    @Test
    fun `greet without name should return 'Hello, World!'`() {
        val entity = template.getForEntity<Greeting>("/rest")

        assertEquals(HttpStatus.OK, entity.statusCode)
//      Could get the content type and then check it, or use let as below
//        val contentType = entity.headers.contentType
//        assertEquals(MediaType.APPLICATION_JSON, contentType)

        entity.headers.contentType?.let {
            assertEquals(MediaType.APPLICATION_JSON, it)
        } ?: fail("Missing or null content-type header")

        assertEquals("Hello, World!", entity.body?.message)
    }

    @Test
    fun `greet with Dolly returns 'Hello, Dolly!'`() {
        val greeting = template.getForObject<Greeting>("/rest?name=Dolly")
        assert(greeting?.message == "Hello, Dolly!")
    }
}

  16. The first test uses the getForEntity method of the template, which returns a ResponseEntity<Greeting>. The response entity gives access to the headers, so the two provided asserts check the status code and the media type of the response. Since the method is from Java and may return null, the Kotlin code uses the ?.let {} construct to only do the assertion if the header is not null.

  17. The actual response is inside the body. By calling getBody, the response is returned as a de-serialized Greeting instance, which allows you to check its message.

  18. The second test uses the getForObject method, which returns the de-serialized response directly. This is simpler, but does not allow access to the headers. You can use either approach in your code.

  19. The tests should now pass. This application only checks HTTP GET requests, because the application doesn’t have any way to save Greeting instances. Once that is added, you could include analogous POST, PUT, and DELETE operations.

  20. If you do a ./gradlew test (or build), you can see the HTML outputs of all the tests in the file build/reports/tests/test/index.html, which you can open in a browser.

3. Building a REST client

This exercise uses the Spring RestTemplate class to access a RESTful web service. The template is used to convert the response into an object for the rest of the system.

  1. Create a new Spring Boot project (either by using the Initializr at http://start.spring.io or using your IDE) called restclient. Change the language to Kotlin and add the Web dependency, but no others are necessary.

  2. Create a service class called JokeService in a com.kousenit.restclient.services package under src/main/kotlin

  3. Add the annotation @Service to the class (from the org.springframework.stereotype package, so you’ll need an import statement)

  4. Add a constructor argument to JokeService called builder of type RestTemplateBuilder. Note that Spring will autowire in the argument, assuming there is only one bean of type RestTemplateBuilder available.

    Tip
    		 If you provide only a single constructor in a class, you do not need to add the @Autowired annotation to it. Spring will inject the arguments anyway

  5. Add a private attribute to JokeService of type RestTemplate called restTemplate and initialize it by calling the build() function on builder.

  6. The site providing the joke API is http://icndb.com, the Internet Chuck Norris Database. The site exposes the jokes through the URL http://api.icndb.com. The API supports a few properties that will be useful here: the client can specify the hero’s first and last names and the joke category.

  7. For our service, add a const, String val called BASE into the companion object and assign it to the URL 'http://api.icndb.com/jokes/random?limitTo=[nerdy]'

  8. Add a function to the service called getJoke that takes two String arguments, first and last and returns a String

  9. Inside the method, create the full URL for the API:

    val url = "$BASE&firstName=$first&lastName=$last"

  10. The RestTemplate class has a getForObject method that takes two arguments: the URL and the class to instantiate with the resulting JSON response. Note on the web page that the resulting JSON takes the form:

    {
  "type": "success",
  "value": {
    "id": 268,
    "joke": "Time waits for no man. Unless that man is Chuck Norris."
    "categories": [
        "nerdy"
    ]
  }
}

  11. Since there are only two nested JSON objects, you can create a class that models them with an inner class. Create a new Kotlin file called Model in the com.kousenit.restclient.json package

  12. The code for the JokeResponse and Value classes is shown below. Note how the properties match the keys in the JSON response exactly. You can use annotations from the included Jackson 2 JSON parser to map them if you like, but in this case it’s easy enough to use the same names in the data classes, as here.

    package com.kousenit.restclient.json

data class JokeValue(val id: Int,
                     val joke: String,
                     val categories: List<String>)

data class JokeResponse(val type: String,
                        val value: JokeValue)

  13. Now the JSON response from the web service can be converted into an instance of the JokeResponse class. Add a line to do that inside the getJoke method. Here is the complete source for the JokeService class:

    package com.kousenit.restclient.services

import com.kousenit.restclient.json.JokeResponse
import org.springframework.beans.factory.annotation.Autowired
import org.springframework.boot.web.client.RestTemplateBuilder
import org.springframework.stereotype.Service
import org.springframework.web.client.getForObject
import java.time.Duration

@Service
class JokeService(@Autowired builder: RestTemplateBuilder) {
    private val restTemplate = builder
            .setConnectTimeout(Duration.ofSeconds(2))  // Optional time out
            .build()

    companion object {
        const val BASE = "http://api.icndb.com/jokes/random?limitTo=[nerdy]"
    }

    fun getJoke(first: String, last: String) =
            restTemplate.getForObject<JokeResponse>("$BASE&firstName=$first&lastName=$last")
                    .value.joke
}

  14. To demonstrate how to use the service, create a test for it. Create a class called JokeServiceTest in the com.kousenit.restclient.services package under the test hierarchy, src/test/kotlin.

  15. This example uses JUnit 5, so you can autowire an instance of the service class directly into the constructor. Note that if you use JUnit 4, you need to add a "late initialized" field of service type, as in lateinit var service: JokeService, but then you are stuck with a var type that you never plan to change.

    class JokeServiceTest(@Autowired val service: JokeService) {
    // ... tests to come ...
}

  16. It will be convenient to log the jokes to the console. Spring Boot provides loggers from a variety of sources. In this case, use the one from the SLF4J library by adding an attribute to the JokeService class:

    import org.slf4j.Logger
import org.slf4j.LoggerFactory

// ...

val logger: Logger = LoggerFactory.getLogger(JokeServiceTest::class.java)

  17. The complete source for the test is:

    package com.kousenit.restclient.services

import org.junit.jupiter.api.Test
import org.slf4j.Logger
import org.slf4j.LoggerFactory
import org.springframework.beans.factory.annotation.Autowired
import org.springframework.boot.test.context.SpringBootTest

@SpringBootTest
@TestInstance(TestInstance.Lifecycle.PER_CLASS)
internal class JokeServiceTest(@Autowired val service: JokeService) {
    val logger: Logger = LoggerFactory.getLogger(JokeServiceTest::class.java)

    @Test
    internal fun `joke using Craig Walls should have the words Craig or Walls`() {
        val joke = service.getJoke("Craig", "Walls")
        logger.info(joke)
        assert(joke.contains("Craig") || joke.contains("Walls"))
    }
}

  18. Feel free to change the name of the hero to anyone you prefer. (Craig Walls is the author of the Manning book Spring in Action.)

  19. Execute the test and make any needed corrections until it passes.

4. Accessing the Google Geocoder

Google provides a free geocoding web service that converts addresses into geographical coordinates.

This exercise uses the RestTemplate to access the Google geocoder and converts the responses into objects.

  1. The documentation for the Google geocoder is at https://developers.google.com/maps/documentation/geocoding/intro. Take a look at the page there to see how the geocoder is intended to be used. The base URL for the service is (assuming you want JSON responses) https://maps.googleapis.com/maps/api/geocode/json?address=street,city,state. The address parameter needs to be URL encoded and the parts of the address are joined using commas.

    Note
    		 The address components can be anything appropriate to the host country. The URL includes a string which separates the values by commas. The components don’t have to be street, city, and state.

  2. Rather than creating a new project, we’ll add a GeocoderService to the existing restclient project. In that project, add the new class to the services package

  3. Add the @Service annotation to the class so that Spring will automatically load and manage the bean during its component scan at start up.

  4. As before, inject in an instance of RestTemplateBuilder called builder as a constructor argument.

  5. Give the class an attribute of type RestTemplate called restTemplate and initialize it by calling builder.build().

  6. Map the JSON response to classes in a json package. The JSON response for the URL https://maps.googleapis.com/maps/api/geocode/json?address=1600+Amphitheatre+Parkway,Mountain+View,CA is:

    We don’t care about the address components, though the formatted address looks useful. In a json subpackage, add the following classes to the Model.kt file from the previous exercise:

    data class Location(val lat: Double,
                    val lng: Double)

data class Geometry(val location: Location)

data class Result(val formattedAddress: String,
                  val geometry: Geometry)

data class Response(val status: String,
                    val results: List<Result>) {

    val location: Location
        get() = results[0].geometry.location

    val formattedAddress: String
        get() = results[0].formattedAddress
}

  7. Note how you can add your own getter method to a property but implementing a get() function, as done in the Response class for the location and formattedAddress properties.

  8. In the GeocoderService class, add constants for the base URL and a key to the companion object.

    companion object {
   const val BASE = "https://maps.googleapis.com/maps/api/geocode/json"
   const val KEY = "AIzaSyDw_d6dfxDEI7MAvqfGXEIsEMwjC1PWRno"
}

  9. Add a function called getLatLng that formulates the complete URL with an encoded address based on a vararg collection of address components, URL encodes each element, and passes to the rest template’s getForObject method, which returns a Response object. The code is:

    fun getLatLng(vararg address: String): Site {
   val encoded = address.joinToString(",") {
      URLEncoder.encode(it, "UTF-8")
   }
   val url = "$BASE?address=$encoded&key=$KEY"
   return restTemplate.getForObject<Response>(url).let {
      Site(name = it.formattedAddress,
               latitude = it.location.lat,
               longitude = it.location.lng)
   }
}

  10. To make this work, we need an entity called Site. Add a data class to the com.kousenit.restclient.entities package called Site that wraps a formatted address string and doubles for the latitude and longitude. Unlike the Model classes, which exist only to map the JSON data to useful objects, instances of this class could in principle be saved to a database. The code is:

    package com.kousenit.restclient.entities

data class Site(val name: String, val latitude: Double, val longitude: Double)

  11. Now we need a test to make sure this is working properly. Add a test class called GeocoderServiceTests to the com.kousenit.restclient.services package in the test directory src/test/kotlin.

  12. Add the @SpringBootTest annotation to the class.

  13. Autowire in the GeocoderService into the constructor, with the field name service.

  14. As before, add a logger from SLF4J by calling LoggerFactory.getLogger(…​) using the current Java class. Note that since the getLogger method is from Java, Kotlin reports it as a platform type (as Logger! with an exclamation point), indicating that it can’t tell whether the value is nullable or not. Therefore, add the explict type Logger to the field.

  15. Add two tests: one using a city and state of Boston, MA, and one using a street address of 1600 Ampitheatre Parkway, Mountain View, CA. The complete test class is:

    Tip

import org.hamcrest.MatcherAssert.assertThat
import org.hamcrest.Matchers.`is`
import org.hamcrest.Matchers.closeTo
import org.junit.jupiter.api.Test
import org.slf4j.Logger
import org.slf4j.LoggerFactory
import org.springframework.beans.factory.annotation.Autowired
import org.springframework.boot.test.context.SpringBootTest

@SpringBootTest
internal class GeocoderServiceTest(@Autowired val service: GeocoderService) {
    val logger: Logger = LoggerFactory.getLogger(GeocoderServiceTest::class.java)

    @Test

        val site = service.getLatLng("Boston", "MA")
        logger.info(site.toString())

        assertThat(site.longitude, `is`(closeTo(-122.1, 0.02)))
    }

  16. The tests will fail, because there is no value called formattedAddress in the JSON response! This can be fixed in a couple of different ways. You could add an annotation to the formattedAddress field in the Result class that would map it to formatted_address.

    import com.fasterxml.jackson.annotation.JsonProperty

data class Result(@JsonProperty("formatted_address") val formattedAddress: String,
   val geometry: Geometry)

    The @JsonProperty annotation is a general purpose mechanism you can use whenever the property in the bean does not match the JSON field. Run your test again and see that the name value in the Site is now correct.

  17. The other way to fix the issue is to set a global property that converts all camel case properties to underscores during the JSON parsing process. To use this, first remove the @JsonProperty annotation from Result.

  18. Set the required property in the application.properties file in the src/main/resources folder. Inside that file, add the following setting:

    spring.jackson.property-naming-strategy=SNAKE_CASE
    Note
    		 The value of property-naming-strategy is one of the constants declared in the com.fasterxml.jackson.databind.PropertyNamingStrategy class.

  19. Once again run the tests and see that the name field in Site is set correctly.

5. Using the JDBC template

Spring provides a class called JdbcTemplate in the org.springframework.jdbc.core package. All it needs in order to work is a data source. It removes almost all the boilerplate code normally associated with JDBC. In this exercise, you’ll use the JdbcTemplate to implement the standard CRUD (create, read, update, delete) methods on an entity.

  1. Make a new Spring Boot project with group com.kousenit and artifact called persistence using the Spring Initializr. Generate a Gradle build file and select the JPA dependency, which will include JDBC. Also select the H2 dependency, which will provide a JDBC driver for the H2 database as well as a connection pool.

  2. Import the project into your IDE in the usual manner.

  3. For this exercise, as well as the related exercises using JPA and Spring Data, we’ll use a domain class called Officer. An Officer will have a generated id of type Integer, strings for first and last names, and a Rank. The Rank will be an enum, which Kotlin calls an enum class.

  4. First define the Rank enum in the com.kousenit.persistence.entities package and give it a few constants. Note that in Kotlin, Java enum is called enum class.

    package com.kousenit.persistence.entities

enum class Rank {
    ENSIGN, LIEUTENANT, COMMANDER, CAPTAIN, COMMODORE, ADMIRAL
}

  5. Now add Officer as a regular (not data) class with the attributes as specified. This works better with JPA, which is not designed to work with immutable classes. Also note that the id parameter, which is given an initial value of null, is added last to make it easier to omit it when using a positional constructor.

    package com.kousenit.persistence.entities

class Officer(
        var rank: Rank,
        var first: String,
        var last: String,
        var id: Int? = null)

  6. One of the features of Spring Boot is that you can create and populate database tables by define scripts with the names schema.sql and data.sql in the src/main/resources folder. First define the database table in schema.sql

    DROP TABLE IF EXISTS officers;
CREATE TABLE officers
(
    id         INT         NOT NULL AUTO_INCREMENT,
    rank       VARCHAR(20) NOT NULL,
    first_name VARCHAR(50) NOT NULL,
    last_name  VARCHAR(50) NOT NULL,
    PRIMARY KEY (id)
);

  7. Next populate the table by adding the following INSERT statements in data.sql

    INSERT INTO officers(rank, first_name, last_name) VALUES('CAPTAIN', 'James', 'Kirk');
INSERT INTO officers(rank, first_name, last_name) VALUES('CAPTAIN', 'Jean-Luc', 'Picard');

INSERT INTO officers(rank, first_name, last_name) VALUES('CAPTAIN', 'Kathryn', 'Janeway');
INSERT INTO officers(rank, first_name, last_name) VALUES('CAPTAIN', 'Jonathan', 'Archer');

  8. When Spring starts up, the framework will automatically create a DB connection pool based on the H2 driver and then create and populate the database tables for you. Now we need a DAO (data access object) interface holding the CRUD methods that will be implemented in the different technologies. Define a Java interface called OfficerDAO in the com.kousenit.persistence.dao package.

    package com.kousenit.persistence.dao

import com.kousenit.persistence.entities.Officer
import java.util.*

interface OfficerDAO {
    fun save(officer: Officer): Officer
    fun findById(id: Int): Optional<Officer>
    fun findAll(): List<Officer>
    fun count(): Long
    fun delete(officer: Officer)
    fun existsById(id: Int): Boolean
}

    As an aside, the names and signatures of these methods were chosen for a reason, which will become obvious when you do the Spring Data implementation later.

  9. In this exercise, implement the interface using the JdbcTemplate class. Start by creating a class in the com.kousenit.persistence.dao package called JdbcOfficerDAO. Spring Boot makes it possible to autowire in an instance of JdbcTemplate. Prior to that, you had to wire in a DataSource and instantiate the JdbcTemplate.

    class JdbcOfficerDAO(private val jdbcTemplate: JdbcTemplate) : OfficerDAO {
    // ... more to come ...

}

  10. To make Spring detect this as a bean it should manage, add the @Repository annotation to the class

    @Repository
class JdbcOfficerDAO(private val jdbcTemplate: JdbcTemplate) : OfficerDAO {
    // ... as before ...
}

  11. Some of the DAO methods are trivially easy to implement. Implement the count method by executing a queryForObject that uses a SELECT count(*) SQL statement and maps the result to a Long. Since the Java result could be null, use the Elvis operator to return zero in that case.

    override fun count(): Long =
    jdbcTemplate.queryForObject<Long>("select count(*) from officers")

  12. Likewise, the delete method is easy to implement using the update method from the template class. The interesting part is that by putting a ? wildcard in the SQL statement, the template will automatically use a PreparedStatement to execute the SQL

    override fun delete(officer: Officer) {
    jdbcTemplate.update("DELETE FROM officers WHERE id=?", officer.id)
}

  13. The exists method also uses a PreparedStatement with an id, but this time the result should be mapped to a boolean.

    override fun existsById(id: Int) =
    jdbcTemplate.queryForObject(
        "SELECT EXISTS(SELECT 1 FROM officers where id=?)",
        Boolean::class.java, id)

  14. Now for the finder methods. When a SQL query produces a ResultSet, the template asks for an implementation of the RowMapper interface as another argument to the queryForObject method. This interface has a single abstract method called mapRow, which takes the ResultSet and a row number as arguments. The implementation then uses the arguments to convert a row of the result set into a instance of the domain class.

  15. First, add an attribute of type RowMapper called officerMapper that is assigned to a lambda implementing the mapRow(ResultSet, int) method from that interface. This requires a kind of cast by pre-pending the word RowMapper to the lambda.

    private val officerMapper = RowMapper { rs: ResultSet, _ ->
    Officer(id = rs.getInt("id"),
            rank = Rank.valueOf(rs.getString("rank")),
            first = rs.getString("first_name"),
            last = rs.getString("last_name"))
}

  16. Now implement the finder methods using this officerMapper

    override fun findById(id: Int): Optional<Officer> =
    if (!existsById(id)) Optional.empty() else
        jdbcTemplate.queryForObject("SELECT * FROM officers WHERE id=?",
            officerMapper, id)?.let { Optional.of(it) } ?: Optional.empty()

  17. The same row mapper can be used to find all the instances of Officer. The JdbcTemplate uses the query method to automatically iterate over the result set, calling the row mapper for each row to convert it to an Officer, and ultimately returns a collection of officers. The following snippet uses the full lambda, just to show how the syntax works.

    // Simpler version next
override fun findAll(): List<Officer> =
    jdbcTemplate.query("SELECT * FROM officers") { rs: ResultSet, _ ->
        Officer(id = rs.getInt("id"),
                rank = Rank.valueOf(rs.getString("rank")),
                first = rs.getString("first_name"),
                last = rs.getString("last_name"))
    }

  18. Note the simpler alternative is:

    override fun findAll(): List<Officer> =
    jdbcTemplate.query("SELECT * FROM officers", officerMapper)

  19. Finally, for the insert, we’ll take a different approach. While you can write the SQL insert statement and use the update method on the JdbcTemplate, there is no easy way to return the generated primary key. So instead let’s use a related class called a SimpleJdbcInsert. Add a private attribute that instantiates and configures it.

    private val insertOfficer = SimpleJdbcInsert(jdbcTemplate)
    .withTableName("officers")
    .usingGeneratedKeyColumns("id")

    Note how you can specify the table that the insert will use, as well as any generated key columns.

  20. Implement the save method using the SimpleJdbcInsert instance

    override fun save(officer: Officer)=
        insertOfficer.executeAndReturnKey(
                        mapOf("rank" to officer.rank,
                                "first_name" to officer.first,
                                "last_name" to officer.last))
                .let {
                    officer.id = it.toInt()
                    officer
                }

    The argument to the executeAndReturnKey method is a Map, so this code uses the mapOf method that takes a vararg list of Pair instances, here mapping each column name to a value. The function then returns the generated key, which is used to update the officer. The let operation returns its last evaluated expression, so to make that an Officer, the last line is officer.

  21. We need a test case to make sure everything is working properly. Create a test class called JdbcOfficerDAOTest that autowires in the DAO class

In a test class like this, Spring will interpret that to mean that each test should run in a transaction that rolls back at the end of the test. That will keep the test database from being affected by the tests and keep the tests themselves all independent.

    Warning
    		 Do not forget to add @Transactional to the class, or the transactions won’t roll back and the tests won’t be independent of each other.

  23. Add a test for the save method

  24. Test findById but using one of the known ids (which are known because the database is being reset each time)

6. Implementing the CRUD layer using JPA

The Java Persistence API (JPA) is a layer over the so-called persistence providers, the most common of which is Hibernate. With regular Spring, configuring JPA requires several beans, including an entity manger factory and a JPA vendor adapter. Fortunately, in Spring Boot, the presence of the JPA dependency causes the framework to implement all of that for you.

  1. To use JPA, we need an entity. We’ll use the same Officer class from the previous exercise, but this time we will add the appropriate JPA annotations @Entity, @Id, @GeneratedValue, @Table, and @Column

    @Entity
@Table(name = "officers")
class Officer(
        @Enumerated(EnumType.STRING) var rank: Rank,
        @Column(name = "first_name") var first: String,
        @Column(name = "last_name") var last: String,
        @Id @GeneratedValue(strategy = GenerationType.IDENTITY) var id: Int? = null)

    The @Enumerated annotation ensures rank is stored as a string, rather than an ordinal number.

  2. Create a class called JpaOfficerDAO that implements the OfficerDAO interface and adds an EntityManagerFactory as an attribute

    @Repository
class JpaOfficerDAO(@PersistenceContext val entityManager: EntityManager) : OfficerDAO {

    // ... more to come ...
}

    The @PersistenceContext annotation is used to inject an entity manager into the DAO. Normally we would also need to make the class transactional, but in keeping with common practice that can be handled in a service layer. In this particular case, however, we’ll so the transactions in the tests.

  3. The implementations of the individual methods is very simple. Since this is a course on Spring and not on JPA, they are given here without comment. Add them to the JpaOfficerDAO class.

    override fun save(officer: Officer): Officer {
    entityManager.persist(officer)
    return officer
}

override fun findById(id: Int) =
    Optional.ofNullable(entityManager.find(Officer::class.java, id))

override fun findAll(): List<Officer> =
    entityManager.createQuery("select o from Officer o", Officer::class.java)
            .resultList

override fun count() =
    entityManager.createQuery("select count(o) from Officer o")
            .singleResult as Long

override fun delete(officer: Officer) = entityManager.remove(officer)

override fun existsById(id: Int) =
    entityManager.createQuery(
        "SELECT 1 from Officer o where o.id=:id")
        .setParameter("id", id)
        .singleResult != null

  4. The same tests used to check the JdbcOfficerDAO can be done again, just using a different DAO as the class under test. This time add a JdbcTemplate to find all the existing id’s in the database, and implement a private getIds function to extract the current id’s.

    @SpringBootTest

                         @Autowired private val template: JdbcTemplate) {


    private fun getIds() =
            template.query("select id from officers") { rs, _ ->
                rs.getInt("id")
            }

    @Test
    fun `save should return officer with non-null id`() {
        Officer(rank = Rank.LIEUTENANT, first = "Nyota", last = "Uhuru")
                .apply { dao.save(this) }
                .also { assertNotNull(it.id) }
    }

    @Test

        getIds().forEach { id ->
            dao.findById(id)
                    .also {
                        assertTrue(it.isPresent)
                        assertEquals(id, it.get().id)
                    }
        }
    }

    @Test
    fun `officer with id 999 does NOT exist`() {
        assertFalse(dao.findById(999).isPresent)
    }

    @Test
    fun `should be 5 officers in test db`() {
        assertEquals(5L, dao.count())
    }

    @Test
    fun `check officer last names in test db`() {
        dao.findAll()
                .map { it.last }
                .also { lastNames ->
                    assertThat(lastNames, containsInAnyOrder(
                            "Archer", "Janeway", "Kirk", "Picard", "Sisko"))
                }
    }

    @Test
    fun `delete all officers`() {
        getIds().forEach { id ->
            dao.findById(id)
                    .run {
                        assertTrue(this.isPresent)
                        dao.delete(this.get())
                    }
        }
        assertEquals(0L, dao.count())
    }

    @Test

        }

    Several of the tests are going to fail, because we have one other setting we have to modify.

  5. If you run the tests, you see that we quickly run into a problem, which is that the sample data is not there! This is because, by default, Hibernate is in what is called "create-drop" mode, which means it drops the database after each execution and re-creates it on startup. We can prevent that, however, by adding a setting to the application.yml file (rename application.properties to application.yml if necessary):

    spring:
    jpa:
        show-sql: true
        hibernate:
            ddl-auto: update
        properties:
            hibernate.format_sql: true

    We switched the spring.jpa.hibernate.ddl-auto property to update (other options are create, create-drop, and validate), which will add columns as necessary but not drop any tables or data.

7. Using Spring Data

The Spring Data JPA project makes it incredibly easy to implement a DAO layer. You extend the proper interface, and the underlying infrastructure generates all the implementations for you.

Spring Data is a large, powerful API. In this exercise, we’ll just show the basics.

  1. Since we created this project based on the Spring Data JPA dependency, we don’t need to modify the Gradle build file to add it. Note that the build file already includes the required dependencies:

    dependencies {
        implementation 'org.springframework.boot:spring-boot-starter-data-jpa'
        runtimeOnly 'com.h2database:h2'
        testImplementation 'org.springframework.boot:spring-boot-starter-test'
}

  2. Spring Data works by defining an interface that extends one of a few provided interfaces, where you specify the domain class and its primary key type. Therefore, create an interface called OfficerRepository in the com.oreilly.persistence.dao package

    interface OfficerRepository : JpaRepository<Officer, Int> {
}

    The interface can extend CrudRepository, PagingAndSortingRepository, or, as here, JpaRepository. You only have to specify the two generic parameters that represent the domain class and the primary key type. Here we use Officer and Int.

    The framework will now generate the implementations of about a dozen different methods, including all the methods listed in the OfficerDAO interface (which is why those methods were chosen in the first place)

  3. Spring Data will also generate the implementations of additional methods that we declare, as long as we follow a specified pattern.

  4. The test class is similar to the others, except that it’s written in terms of the OfficerRepository bean, so just copy JpaOfficerDAOTests to OfficerRepositoryTests and change the dao field to be of type OfficerRepository:

    @SpringBootTest
@Transactional
class OfficerRepositoryTest(@Autowired val dao: OfficerRepository,
                            @Autowired private val template: JdbcTemplate) {

// ... rest is the same ...
}

  5. The tests should all pass, because the functions in the OfficerDAO interface were chosen to match functions autogenerated by Spring Data.

  6. Once the tests pass, add two dependencies to the Gradle build file: one for the Spring Data Rest project (which will expose the data via a REST interface) and for the HAL browser, which will give us a convenient client to use

    implementation 'org.springframework.boot:spring-boot-starter-data-rest'
implementation 'org.springframework.data:spring-data-rest-hal-browser'

  7. After rebuilding the project, start up the application (using the class with the main method) and navigate to http://localhost:8080. Spring will insert the HAL browser at that point to allow you to add, update, and remove individual elements, which we’ll do in class.
